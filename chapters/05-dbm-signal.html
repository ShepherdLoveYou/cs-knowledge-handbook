dBm · 分贝 · 信号强度

Wi-Fi 图标那个"−31dBm"、路由器规格表那个"22dBm"到底是多少瓦、够不够用——这一章把贯穿几乎所有无线通信的对数计量语言讲透,并用一次真实的收发实测数字,带你把信号从发射端"跌"到接收端的全过程算一遍。

上一章结尾埋了一个数字:某个 regulatory domain 下,2.4GHz 每条信道的 max_tx_power 标着 20dBm。这一章要把"dBm"这个符号彻底吃透——它不是随手起的怪名字,而是工程师专门为了应付无线信号那种"发射端几百毫瓦、接收端几纳瓦"的悬殊量级,量身定做的一套对数语言。

为什么信号强度是个负数

系统托盘里的 Wi-Fi 图标切换到"详细信息",经常能看到一行奇怪的读数,比如 −31dBm——不是格数、不是百分比,而是一个负数,还越接近 0 反而信号越好。与此同时,路由器规格书或者 iw/netsh 这类工具报出的发射功率却常常是正数,比如 22dBm。同一个字母组合"dBm",一会儿是接收端的负数,一会儿是发射端的正数,直觉上很难对上号。

根子在于无线信号从天线发出去到被另一端天线收到,功率要经历极端悬殊的跨度:发射端动辄上百毫瓦,几米开外的接收端往往只剩几十亿分之一瓦——直接写成瓦特,不是一长串 0,就是科学计数法,既难读也难心算。工程师的解法是一套三件套语言:dB(比值的对数单位)、dBm(把参考点钉死在 1 毫瓦上的绝对功率单位),以及建立在它们之上的 RSSI 信号分级、路径损耗、EIRP 几个配套概念。这一章把这套语言从头拆开,并用一组真实测到的数字——AP 发射 22dBm、笔记本收到 −31dBm——带着从头走一遍。

分贝:比值的对数,不是绝对量

分贝(decibel,dB)的定义只有一件事:两个功率之比,取以 10 为底的对数,再乘以 10:

dB = 10 · log10( P1 / P2 )

注意这里没有配一个单位——分贝表示的永远是比值,P1 比 P2 大多少倍,而不是某个绝对的"多少瓦"。这个设计对通信工程极其顺手:一条信号链路往往要串联好几级放大器、衰减器、天线、馈线,每一级都是把功率乘上一个倍数;换成分贝后,级联相乘变成了级联相加——总增益的 dB 数,就是每一级 dB 数直接加总,不用再算连乘。

深挖 · "dB"这个名字从哪来

分贝最早不是拿来量声音的,而是电话工程师在 1920 年代发明的线路衰减单位。贝尔实验室 1924 年提出"传输单元"(Transmission Unit,TU)描述电话线信号每传输一段标准距离衰减多少,1928 年正式改名为 decibel——十分之一个 bel,以贝尔实验室的技术命脉、电话发明人 Alexander Graham Bell 命名[5][6]。后来这套对数记法被声学借用去表示声压级,才有了"分贝=音量"的日常印象;但它的本行,一直是工程上的"比值"。

这个类比可以再钉实一层:音响工程里常见的经验法则是,声压级每提高约 10dB,人耳感觉到的响度大致翻一倍[15]——这跟本章"+10dB=功率×10"用的是同一套对数运算,却是两件不同的事:后者量的是客观功率比值,是精确恒等式;前者量的是人耳主观感知的响度,是心理声学的经验规律,数值上并不相等,只是恰好都落在"10 这个量级"。音量旋钮拧过同样的角度,响度听起来的变化却一点不"线性",正是因为人耳对声音强弱的感知本身就是压缩的(近似对数式的)——分贝这套刻度当初能从电话工程"出圈"变成日常语言里的"音量",靠的就是这份天生合拍。

原理 · 级联系统为什么能直接加分贝

一条信号链路——比如天线接收 → 馈线衰减 → 低噪放大器 → 混频器——数学上是好几个环节的功率倍数连乘:P_out = P_in × G1 × G2 × G3 × …。两边取 10·log10 后,乘法按对数法则拆成加法:10log(G1×G2×G3)=10logG1+10logG2+10logG3。于是工程师分析整条链路时,只要把每一级的 dB 值直接加减,不用先还原成线性倍数再连乘、算完再取一次对数——这正是信号与系统里分析级联 LTI(线性时不变)系统最常用的手法,见 14 信号与系统。

dBm:把参考点钉死在 1 毫瓦

dB 只能表示"谁比谁大多少倍",要变成一个能直接读数的绝对功率单位,还差一步:钉死一个参考功率。dBm 就是把这个参考点定在 1 毫瓦(1mW) 上——m 就是 milliwatt[1]:

dBm = 10 · log10( P / 1mW )
P   = 1mW · 10^(dBm/10)

反过来推,记住几个常用锚点就够用日常读数:

dBm功率(mW)常见场景
0dBm1mW参考零点
10dBm10mW低功耗蓝牙 / IoT 芯片常见发射功率
20dBm100mW不少地区 2.4GHz Wi-Fi 单信道功率上限[11]
22dBm≈158mW本章例子:AP 实测发射功率
30dBm1000mW(1W)点对点专用无线网桥常见量级

速算规则:+3dB ≈ ×2,+10dB = ×10

把 P2=2×P1 代入定义:10·log10(2) ≈ 10×0.301 = 3.01,所以功率翻一倍约等于 +3dB;把 P2=10×P1 代入:10·log10(10) = 10,不多不少刚好 +10dB[4]。这两条是无线电工程师随口就能心算的规则:

  • +3dB ≈ ×2(精确值 ×1.995,工程上直接当 2 用)
  • +10dB = ×10(精确)
  • 组合起来:+13dB≈×20,+20dB=×100,+23dB≈×200……

拿本章的例子练一遍心算:AP 报的发射功率是 22dBm。拆成 20+2:20dBm 已知是 100mW;剩下的 2dB 比 0dB(×1)多一点、比 3dB(×2)少一点,估个"接近但不到两倍",毛估 150~160mW——精确计算是 10^2.2≈158.5mW,估算相当准。这种"先拆成整十 + 零头"的心算法,是读硬件规格书最常用的手感。

避坑 · dBm 能相减,不能直接相加

两个 dBm 值相减没问题,结果是合法的 dB(比值)——因为两边共同的"1mW 参考点"在减法里正好相互抵消,比如下一节要算的"发射(dBm) − 接收(dBm) = 路径损耗(dB)"。但两个 dBm 值相加没有物理意义:两路信号功率要合并,必须先各自换算回 mW 相加,再把和转换回 dBm——不能拿 dBm 数字直接相加当结果,那样算出来的数字没有对应的物理量。

路径损耗:从发射到接收,信号去哪了

电磁波离开天线之后,能量按球面向四面八方扩散——距离越远,同样的总功率摊到的球面积越大,单位面积上的功率密度就越低,这是纯几何上的反平方规律。工程师 Harald Friis 在 1946 年给出的 Friis 传输公式,把这条几何规律和收发天线增益放在一起,推出了接收功率与发射功率之比同距离、波长的关系;只考虑纯真空、无任何障碍物、天线均为理想全向的情况,这个比值取倒数就是自由空间路径损耗(Free-Space Path Loss,FSPL)[2]。换算成分贝、距离单位用公里、频率单位用 GHz 后,是一个很好记的形式:

FSPL(dB) = 20·log10(d_km) + 20·log10(f_GHz) + 92.45

距离和频率前面都是 20 倍而不是 10 倍,因为功率损耗正比于距离和频率的平方——距离翻倍,损耗多 +6dB(两个 +3dB);频率翻倍,损耗同样多 +6dB。同一条公式换个角度看:距离变成 10 倍,20·log10(10)=20,损耗就多 +20dB——这正是天线工程里"距离每变 10 倍,路径损耗多 20dB"这条经验法则的来历,和前面"+10dB=×10"是同一个数、不同的物理量。

实战锚点 · 22dBm → −31dBm,53dB 去哪了

回到本章开头的真实读数:旁路由这台 AP 报的发射功率是 22dBm,笔记本站在附近测到的 RSSI 是 −31dBm。跟着算一遍:

总衰减 = 发射(dBm) − 接收(dBm) = 22 − (−31) = 53dB

换算成线性倍数:10^(53/10) = 10^5.3 ≈ 199,500 倍
→ 接收到的功率只有发射功率的约 1/20万

若这 53dB 全部记在自由空间路径损耗头上,2.4GHz 频段代入 FSPL 公式反推距离:
  53 = 20·log10(d_km) + 20·log10(2.4) + 92.45
  53 = 20·log10(d_km) + 100.05
  d_km ≈ 10^((53−100.05)/20) ≈ 0.0044km ≈ 4.4米

理想自由空间模型下,53dB 只对应约 4~5 米——但现实中的房间有墙体、家具、人体,这些都会叠加额外损耗,实际路径损耗几乎总是比同等距离下的 FSPL 理论值更大。这也是为什么 FSPL 只能当理论下限,不能直接当"预测实际覆盖"的公式用:它告诉你"最好情况下"信号能有多强,真实环境只会更差、不会更好。

RSSI 与信号强度分级

RSSI(Received Signal Strength Indicator,接收信号强度指示)就是网卡收到信号后报出的那个 dBm 数字。行业里没有一份全球统一的"多少 dBm 算好"标准,但综合多份工程参考,大致的经验分级是[7][8]:

RSSI(约)分级典型体验
≥ −50dBm极好 Excellent几乎不受任何应用限制,通常离 AP 很近
−50 ~ −60dBm良好 Good视频会议、云应用等大多数场景稳定
−60 ~ −70dBm一般 Fair网页、邮件够用,高带宽应用开始吃力
−70 ~ −80dBm较差 Poor速度明显下降,丢包概率上升
< −80dBm不可用 Unusable逼近噪声地板,连接大概率不稳定

本章例子里的 −31dBm,妥妥落在"极好"这一档——和前面反推出的"约 4~5 米近距离"的结论完全对得上。

避坑 · RSSI 不是跨厂商标准化的数值

IEEE 802.11 标准里,RSSI 严格来说只定义成一个 0~255 的任意整数量程,具体每一格对应多少 dBm、量程上限(RSSI_Max)是多少,标准并不强制统一,而是留给每家芯片厂商自己定,不同厂商网卡之间 RSSI 数值的换算方式也不一样[9]。换句话说,一块网卡报的 −31dBm 和另一块不同芯片网卡报的 −31dBm,底层原始量程和换算公式可能完全不同——同一台设备前后对比、或者同芯片型号的设备互相比较是可靠的,但拿两个不同厂商的"信号格数"或 RSSI 数字直接比大小,并不严谨。

EIRP:发射功率 + 天线增益

前面算的 22dBm,是发射机送进天线之前的功率;天线本身还会把这些功率往某个方向"聚拢",聚拢的效果就是天线增益(单位 dBi,相对理想全向天线的倍数)。把两者按 dB 直接相加,就是有效全向辐射功率(Effective Isotropic Radiated Power,EIRP)——它回答的问题是:"如果换成一个完美的、朝各个方向均匀撒能量的理想天线,得给它多大功率,才能在信号最强的那个方向做到跟现在这个真实天线一样强?"[3]

EIRP(dBm) = 发射功率 Pt(dBm) + 天线增益 Gt(dBi)

示例(引自 Ubiquiti 无线工程培训资料):
  Pt = 20dBm(100mW) + Gt = 3dBi  →  EIRP = 23dBm(≈200mW)

各国无线电管理机构真正拿来画监管红线的是 EIRP,而不是芯片输出端的裸发射功率——因为决定"会不会干扰别人"的,是天线聚拢后那个最强方向上的等效功率[10]。

深挖 · EIRP、ERP 和天线增益的两种参照系

天线增益有两种常见参照系:dBi 相对理想全向天线(isotropic),dBd 相对最基础的半波偶极子天线(dipole)。因为半波偶极子本身比理想全向天线就多出约 2.15dB 的方向性增益,同一根天线标 dBd 会比标 dBi 小 2.15;类似地,ERP(相对偶极子的有效辐射功率)和 EIRP(相对全向天线)描述同一根天线时也总是差 2.15dB:EIRP(dBm) ≈ ERP(dBm) + 2.15dB[3]。规格书上看到 ERP 和 EIRP 数字对不上,先检查是不是这 2.15dB 的参照系差异,而不是先怀疑厂商标错了。

地区/规则2.4GHz EIRP 上限备注
欧盟 ETSI100mW(20dBm)硬上限,大多数欧洲及采用同规则地区适用[11]
美国 FCC Part 15(点对多点)最高 4W(36dBm)天线增益每超 6dBi,发射机裸功率需等量下调以维持该上限[11][14]
避坑 · EIRP 受各国法规硬上限管制

不是功率开得越大、天线增益堆得越高,覆盖就"越强越好"——民用 2.4GHz 频段的 EIRP 在大多数国家都有强制上限(见上表)。国内外买到的路由器、网卡出厂设置已经按所在地区法规锁好了上限,私自刷高发射功率或者换用高增益天线,很容易就超出合规范围,也可能干扰同频段的其他用户。

以表中美国 FCC 规则为例还有一层容易踩错的细节:点对多点(point-to-multipoint,面向多个客户端的常规 AP)和点对点(point-to-point,专用定向链路)适用的天线增益换算规则并不相同。点对多点系统一旦天线增益超过 6dBi,裸机功率必须等量(1:1)下调以维持 36dBm 的 EIRP 硬上限;只有专用的固定点对点链路,才能享受"每超 3dB 增益只需降 1dB 功率"的更宽松例外,允许 EIRP 随高增益天线继续爬升[14]。把点对点的宽松例外套用到点对多点场景,会实打实地超出合规上限。

接收灵敏度与动态范围

接收灵敏度是接收机能够可靠解调出数据的最低输入功率门槛,单位同样是 dBm。这个门槛从来不是单一值,而是随调制方式和信道带宽剧烈变化:802.11 标准给 20MHz 信道定的最低接收灵敏度要求里,最稳健的 BPSK(1/2 码率)只要 −82dBm 就能工作,而追求高速率的 256-QAM(3/4 码率)需要 −59dBm 以上——同一张网卡、同一条信道,两种调制方式对信号强度的要求相差 23dB,接近 200 倍功率[12]。这就是为什么人从路由器旁边走远、信号变差时,网速是渐渐变慢而不是突然掉线:网卡在实时把调制方式往更稳健但更慢的档位切换,直到信号跌破哪怕最保守调制方式的门槛,连接才会真正断开。调制方式如何用信噪比换速率,属于信号与系统的范畴。

动态范围则是接收机能处理的最强信号(再强前端就饱和失真)和最弱信号(再弱就跌破灵敏度门槛、淹没进噪声地板)之间的比值,同样用 dB 表示[13]。举个更极端的量级参照:−90dBm 这类逼近噪声地板的信号,换算成绝对功率是 1mW×10⁻⁹=10⁻¹²W,也就是约 1 皮瓦(pW)——比本章开头说的接收端"几十亿分之一瓦",还要再往下探两三个数量级。灵敏度门槛能压到这个量级,天线设计、屏蔽和前端低噪声放大器的种种讲究,为的正是这最后几个 dB。动态范围窄的接收机两头都不讨好:离 AP 太近容易"信号太强反而听不清"(前端饱和削波),离得太远又直接跌出可用范围——这也是专业 Wi-Fi 勘测通常建议别紧贴 AP 测试的原因,数据会因为前端过载而失真、参考价值反而下降。

本章要点

本章要点
  • dB = 比值的对数单位(10·log10(P1/P2)),本身无量纲,级联系统的增益/损耗可以直接相加,得名于电话工程师 Alexander Graham Bell。
  • dBm = 把参考点钉在 1mW 的绝对功率单位:dBm=10·log10(P/1mW);0dBm=1mW,10dBm=10mW,20dBm=100mW。
  • 速算:+3dB≈×2,+10dB=×10(故 +13dB≈×20,+20dB=×100);两个 dBm 可以相减(得到 dB),不能直接相加。
  • FSPL(自由空间路径损耗)= 20·log10(d_km)+20·log10(f_GHz)+92.45dB,只是理想下限,真实环境损耗只会更大。
  • 实测:AP 发射 22dBm,客户端收到 −31dBm,总衰减 53dB(约 20 万倍功率跌落),对应自由空间理想距离约 4~5 米。
  • RSSI 信号分级(约):≥−50 极好,−50~−60 良好,−60~−70 一般,<−70 渐差;但 RSSI 本身不是跨厂商标准化的量。
  • EIRP = 发射功率(dBm)+ 天线增益(dBi),受各国法规上限管制(如欧盟 2.4GHz 上限 100mW/20dBm)。
  • 接收灵敏度 = 可靠解调的最低功率门槛,随调制方式浮动(BPSK −82dBm ~ 256-QAM −59dBm);动态范围 = 最强可处理信号与灵敏度门槛之间的 dB 差。
