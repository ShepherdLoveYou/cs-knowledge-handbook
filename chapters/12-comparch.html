1. 为什么要打开这层"黑箱"

第 08 章把处理器的「最大处理器状态」从 100 拧到 99,Turbo Boost 被摁住,风扇跟着安静下来;第 09 章里,DellFanCmd 这类想直接操控风扇的工具一碰 EC(嵌入式控制器),就被 Secure Boot 连带的驱动签名机制拦在 ring 0 门外。这两章都是在处理器这层"黑箱"外面打转——知道该拧哪个开关、知道哪扇门锁着,却没说清楚黑箱里面到底在发生什么:执行代码为什么会发热?"频率""缓存""总线"这些词,具体对应着哪块电路?EC 又是靠什么物理通道,接进这整台机器的?

这正是计算机组成原理(computer organization)要回答的问题——它是操作系统与编程语言之下、晶体管电路之上的那一层,是"软件为什么能在硬件上跑起来"的答案;再往下配一点数字电路(digital logic)基础,因为总线上跑的每一个 0/1,最终都是一个个逻辑门和触发器在物理世界里的电压高低。本章按"一块芯片的骨架 → 一条指令真正被执行 → 一段代码为什么让风扇转起来"的顺序,把这条链走一遍。

2. 冯诺依曼架构:程序也是数据

任何一台通用计算机拆到最后都逃不开五个部件:运算器(ALU,Arithmetic Logic Unit;完成加减乘除、与或非等具体运算)、控制器(CU,Control Unit;指挥其他部件在正确的时刻做正确的事)、存储器(存指令,也存数据)、输入设备、输出设备。运算器和控制器通常封装在同一块芯片里,合称 CPU。1945 年冯·诺依曼在 EDVAC 报告里定下的关键决定,是让指令和数据存进同一块存储器——这就是"存储程序(stored-program)"概念:程序不再是拨线板上焊死的电路,而是像数据一样能被读取、修改,编译器、乃至自我修改代码,归根结底都靠这一点。

CPU 靠一个不断循环的动作把指令变成结果:取指(fetch)——按程序计数器(PC)里的地址,从存储器读出一条指令;译码(decode)——控制器搞清楚这条指令要做什么、要用哪些寄存器;执行(execute)——运算器动手算,结果写回寄存器或存储器,PC 同时指向下一条指令。这个 fetch-decode-execute 循环,从 1940 年代到今天没有变过,变的只是每一步做得多快、多条指令能不能重叠着做(第 5 节的流水线)。

通电的第一瞬间,PC 里已经被硬件钉死了一个固定地址,CPU 从那里取出的第一批指令,来自主板上的固件——正是 第 01 章刷机时打交道的 BIOS / UEFI / coreboot 那一层。固件本质上也是"程序",一样被这套 fetch-decode-execute 循环取指、译码、执行,只是它的起始地址不需要"谁来告诉 CPU",出厂时就已经焊在硬件里。

冯诺依曼架构有一个天生的软肋:指令和数据挤在同一条总线上,CPU 同一时刻只能取指令,或者存取数据,不能两者兼得——这就是冯诺依曼瓶颈。与它相对的哈佛架构(Harvard architecture)干脆把指令和数据分成两块独立的存储器、两条独立的总线,取指和存取数据可以同时进行。现代 x86 / ARM 处理器对外呈现的仍是冯诺依曼模型(指令和数据在同一个地址空间里),但芯片内部几乎都悄悄做了一层"改良哈佛"折衷——把最靠近 CPU 的一级缓存拆成指令缓存(I-Cache)和数据缓存(D-Cache)两块独立通路。第 6 节的存储层次,正是这套折衷方案落地的地方。

展开:纯哈佛架构今天用在哪

真正"指令、数据物理上完全分离"的纯哈佛架构,今天常见于对确定性和体积更在意的微控制器与数字信号处理器,而不是笔记本、服务器这类通用 CPU——通用处理器选的是"外表冯诺依曼,内部改良哈佛"这条折衷路线,既保留了编程模型的简单(指令数据同一地址空间,编译器 / 操作系统好处理),又让取指、访存不至于互相打架。

3. 数制与编码:机器怎么表示数字

存储器里的每一位(bit)只有 0/1 两种状态,对应电路里"低电压 / 高电压"两档,这也是计算机天生用二进制、而不是人类习惯的十进制的原因。四个二进制位分一组,恰好对应一位十六进制数字(0–F),所以内存地址、机器码常用十六进制书写——不是计算机"喜欢"十六进制,只是图人类阅读方便。

无符号整数好办,n 位二进制能表示 0 到 2n−1;麻烦的是负数。今天几乎所有处理器采用的方案叫补码(two's complement):最高位当符号位(0 正、1 负),负数的补码等于该数绝对值的二进制表示按位取反后加 1。这样设计的好处是——CPU 的加法器电路完全不用为减法、为符号另开一条电路,"加上一个负数"和"减去一个正数"在补码体系下用的是同一套硬件。n 位补码能表示的范围是 −2n−1 到 2n−1−1(8 位就是 −128 到 127),比对称的原码 / 反码多出一个可表示的负数,因为补码只有一种"零"的编码,不像原码 / 反码正零、负零各占一个编码位置,省下来的编码就划给了负数那一侧。

4. 逻辑门与时序电路:从晶体管到"记忆"

补码解决了"怎么表示数",这一节回答"电路怎么算"。逻辑门(logic gate)是数字电路最基本的积木——每个门有若干个 0/1 输入,产出一个 0/1 输出,今天绝大多数逻辑门用 MOSFET(金属-氧化物-半导体场效应晶体管)实现,但每个门对外的行为,一张真值表就能完全描述。

NOT(取反)只有一个输入:输入 0 出 1,输入 1 出 0。值得记住的是 NAND 和 NOR 各自都是"万能门"(universal gate)——只用 NAND(或者只用 NOR),就能拼出 AND、OR、NOT 里的任何一个,进一步就能拼出加法器、寄存器,直至一整块 CPU。这也是为什么真实芯片的标准单元库(standard cell library)常以 NAND/NOR 为最基本的构建单元。

XOR(异或,exclusive OR):两个输入不同时输出 1、相同时输出 0(Y = A⊕B);XNOR是 XOR 取反,两个输入相同则输出 1,常用于判断两位是否相等。XOR 还有一个不太显眼但很关键的身份——两个 1 位数相加时,"和"这一位正是两个加数的 XOR,"进位"这一位则是两个加数的 AND,这正是图 1 里运算器(ALU)做加法的电路基础,XOR/XNOR 因此常与 AND/OR/NAND/NOR 一起出现在真值表里对照着看。

深挖 · 十亿个晶体管说到底是同一种门拼出来的

典型 CMOS 实现里,一个 2 输入 NAND 门只需要 4 个晶体管(2 个 PMOS 并联 + 2 个 NMOS 串联);而 AND 门等价于"NAND 后面再接一个 NOT",要多花 2 个晶体管、变成 6 个。"用 NAND 拼出一切"不只是数学上好看的抽象游戏,更是真实芯片省晶体管、省功耗、省面积的工程选择——一颗现代 CPU 动辄几十亿个晶体管,省下来的每一个都要乘以几十亿倍。

以上都是组合逻辑(combinational circuit)——输出只取决于当前输入,没有"记忆"。但寄存器要记住上一条指令算出来的值,程序计数器要记住"下一条该执行哪一条",这需要时序逻辑(sequential circuit):输出不仅取决于当前输入,还取决于电路之前的状态。时序逻辑的最小记忆单元叫触发器(flip-flop)——一个触发器能稳定保存 1 个 bit,靠一个时钟信号(clock)统一"节拍",只有在时钟边沿到来的那一刻才更新状态,其余时间死死保持原值不变。把若干个触发器并排,就组成一个寄存器(register)——第 2 节提到的程序计数器 PC、指令寄存器 IR,本质都是若干个触发器拼起来的寄存器。

5. CPU 数据通路与流水线

把取指-译码-执行三步老老实实做完一条指令、再开始下一条,是最直白的实现,但意味着大部分电路在大部分时间里都闲着——ALU 在译码阶段没事干,取指电路在执行阶段也没事干。流水线(pipelining)的想法很朴素:把指令处理拆成几个独立阶段,像工厂流水线一样,不等第一条指令走完全部阶段,第二条指令就可以进入第一阶段。经典 RISC 5 级流水线把整个过程拆成 IF(取指)→ ID(译码,顺带从寄存器堆读操作数)→ EX(运算)→ MEM(访存)→ WB(写回寄存器)。理想情况下,5 级流水线满载时的吞吐量能逼近单周期实现的 5 倍。

流水线不是没有代价——几条指令同时"在流水线里"时,会互相绊倒,统称流水线冒险(hazard):

类型起因例子常见解法
结构冒险
structural		两条指令想同时用同一个硬件资源取指(IF)要读存储器,同时前面某条指令处于访存(MEM)阶段也要读存储器,共用同一个内存端口就会撞车拆出独立的指令 / 数据缓存通路(第 2 节的"改良哈佛")

原理 · 408 教材怎么给冒险分类

计算机组成原理教材(以及 408 考纲)把流水线冒险严格分成这三类,是因为解法完全不同:结构冒险靠"多配一份硬件"根治;数据冒险靠"提前把数据递过去"(前推)或者"等一等"(停顿);控制冒险则没有"提前拿到答案"这个选项——分支到底往哪走,只有真算完才知道,只能猜,猜错了就把猜错的那几条指令作废重来,这个代价叫"错误预测惩罚(misprediction penalty)",在现代深流水线上可能高达 15–20 个时钟周期。

展开:分支预测靠什么"猜"

最简单的静态预测只用一条经验规则,比如"往回跳的分支(循环末尾常见)大概率会跳,往前跳的大概率不跳";现代 CPU 普遍用动态预测——专门的硬件表记录"这条分支指令最近几次是跳还是不跳",按历史统计猜下一次,猜错了再回去更新记录。这套投机执行机制效果很好,但也有代价,见本章第 9 节。

6. 存储层次与 Cache:为什么会有 L1/L2/L3

流水线让 CPU 一个时钟周期能干的活变多了,但存储器的速度跟不上——现代 CPU 一个时钟周期通常在零点几纳秒级别,而主存(DRAM)一次访问动辄上百个时钟周期。如果每条指令、每次取数据都直接捅到主存,流水线基本等于白建。解法是在 CPU 和主存之间垫上一层甚至好几层又小又快、造价也更贵的存储器——缓存(cache)。

缓存能生效,靠的是程序访问内存的局部性原理(locality of reference):时间局部性——一个地址如果刚被访问过,很可能很快再被访问一次(循环体里的变量);空间局部性——一个地址被访问后,它附近的地址很快也可能被访问到(数组的连续遍历)。缓存把最近用过、以及紧挨着它的一小块数据整体搬过来,大多数时候后面的访问就能在缓存里"命中(hit)",不用再等主存。

层级典型容量典型延迟(时钟周期)由谁管理
L1(常拆 I-Cache / D-Cache)数十 KB,每核心私有约 4硬件
L2数百 KB 到 1MB,每核心私有约 10硬件

换一个更贴近生活的说法:寄存器像手边正在用的调料,伸手就到;L1/L2/L3 像灶台抽屉、厨房柜子、储藏室,一层比一层要多走几步才拿得到;主存像楼下的超市,东西够多但得专门跑一趟;外存则像更远的仓库,一次进的货最多,但也最慢——离 CPU 越远,能放的东西越多,取一次要等的时间也越长,这正是存储层次要在"快"和"大"之间做的取舍。

换句话说,缓存不是一层"更大的内存",而是一整套"用小而快的层,替大而慢的层挡住大部分请求"的分级体系——从寄存器(第 4 节提到的触发器组),到 L1、L2、L3,到主存,到最外层的 SSD/HDD,一路容量变大、速度变慢、单位成本变便宜。第 11 章会讲操作系统怎么用虚拟内存把"主存不够用"这件事,悄悄挪到更慢的外存上接着扛;第 13 章讲算法复杂度时提到的"访问模式对实际性能的影响",很大程度上也是这套局部性原理在数据结构选择上的体现。

7. 总线与 I/O:CPU 怎么和 EC、外设对话

图 1 里连接 CPU、存储器和输入输出设备的那三条线,合称总线(bus)——一组被多个部件共享的物理线路。地址总线单向,由 CPU 发出,指定"要读写的是哪个地址";数据总线双向,承载真正搬运的数据本身;控制总线双向,传递"读还是写""就绪了没有"这类同步信号。三条线共享同一套物理通路,正是第 2 节"冯诺依曼瓶颈"在硬件上最直接的体现。

换成一个生活场景更好理解:三条总线像小区里的一条共享车道——地址总线是门牌号,告诉车该往哪家送;数据总线是车上实际搬运的货物;控制总线是路口的红绿灯,协调什么时候该收货、什么时候该放行。车道只有一条,同一时刻只能过一路车,这正是冯诺依曼瓶颈最直观的物理原型。

CPU 怎么知道该找存储器还是找输入输出设备?现代主流方案是内存映射 I/O(memory-mapped I/O)——把外设的寄存器也编进和内存一样的地址空间,CPU 用同一套读写指令就能操作它们。但 x86 处理器额外保留了一套独立的 I/O 地址空间(端口 I/O / port-mapped I/O),用专门的 IN/OUT 指令访问,一共 64KB 地址,用"端口号"而不是"内存地址"寻址——第 09 章埋下的伏笔,答案就在这里:ACPI 规范第 12 章《Embedded Controller Interface Specification》把 EC(嵌入式控制器)的通信协议钉死在两个 8 位端口上——0x66(命令 / 状态口)和 0x62(数据口)。BIOS 或操作系统驱动往 0x66 写一个命令字节(比如 0x80–0x84 这几个值分管读写 EC 内部不同寄存器),再从 0x62 读写数据,一来一回,没有 USB、PCIe 那些现代总线的握手协议,朴素但管用。DellFanCmd 这类工具想绕开厂商预设的风扇曲线,归根结底就是想直接对这两个端口发号施令——而这需要 ring 0 权限,又绕回第 09 章讲过的驱动签名问题。

8. 跟着算一遍:Turbo Boost 与散热降频

实战锚点 · 把本章讲的每一层都走一遍

为什么同一段脚本,这次笔记本风扇冲到最响,下次却安安静静?把前面几节串起来,答案是一条完整的因果链:

① 高负载代码让流水线(第 5 节)持续满载,现代核心还叠加乱序执行 / 多发射,多个 ALU 同时翻转晶体管;② 晶体管翻转频率越高,动态功耗越大——CMOS 电路的动态功耗近似 P ≈ C·V²·f(电容 × 电压平方 × 频率),频率 f 每往上走一档,功耗跟着走高;③ 功耗最终转化为热量,一旦顶到 Intel Turbo Boost 允许的功耗、电流、温度三条上限中的任意一条,处理器就会主动降频——第 08 章把「最大处理器状态」从 100 拧到 99,本质就是提前把"允许冲上限"这个开关焊死;④ 温度信号通常也要经过 EC 这一层(第 7 节讲的 0x62/0x66 端口),风扇转速由 BIOS/EC 固件按自己的曲线独立决定,操作系统本身往往看不到这个决策过程(第 09 章的 SMM / ring −2);⑤ 同一段代码在不同数据规模下,缓存命中率(第 6 节)、分支是否可预测(第 5 节)都会不同,每条指令的平均周期数(CPI,Cycles Per Instruction)因此不同,乘以固定的周期时长后,实际耗时和发热速率也就跟着不同,触发 Turbo 降频的时长自然不同——风扇响不响、响多久,从头到尾都是这条链条的最终输出,而不是一个孤立的"玄学"现象。

9. 避坑:投机执行不是免费的午餐

避坑 · 分支猜错事小,猜错时"留下的痕迹"事大

第 5 节提过,控制冒险靠分支预测 + 投机执行来掩盖——CPU 猜一个方向,提前把后面的指令跑起来,猜对了白捡性能,猜错了就把这些指令的结果整个作废,架构上像没发生过一样。问题在于"没发生过"只对寄存器、内存这些程序看得见的状态成立;投机执行过程中,缓存(第 6 节)这类看不见的微架构状态是真实被改动过的,不会跟着一起回滚。2018 年初公开的 Meltdown 与 Spectre 这两类漏洞,正是利用这一点:Meltdown 利用的是处理器在乱序执行时没有及时检查权限,让 CPU 投机执行一次本该越权的内核内存读取;Spectre 利用的是诱导分支预测器往错误方向"猜"。机制细节不同,但都靠同一个物理效应收尾——投机执行留在缓存里的痕迹,可以被攻击者用"缓存命中比未命中快得多"这个时间差,一位一位地测出来,这类攻击不修改任何数据,单纯靠"性能优化机制本身"泄密。这是流水线、缓存这些第 12 章机制,与 第 15 章密码学 / 安全模型碰到一起时最有名的一次交叉。

本章要点
  • 冯诺依曼架构:指令和数据存在同一块存储器里,靠 fetch-decode-execute 循环驱动;现代 CPU 用 I-Cache/D-Cache 分离做了"改良哈佛"式的折衷。
  • 二进制与补码:补码(取反加 1)让加法电路可以直接处理负数,n 位补码范围是 −2n−1 到 2n−1−1。
  • 逻辑门与时序电路:7 种基本门(AND/OR/NOT/NAND/NOR/XOR/XNOR)靠晶体管实现;NAND/NOR 是"万能门";触发器 + 时钟组成寄存器,是"记忆"的最小单元。
  • CPU 流水线:经典 5 级(IF/ID/EX/MEM/WB)让多条指令重叠执行提升吞吐;结构、数据、控制三种冒险,分别靠拆分部件、前推 / 暂停、分支预测解决。
  • 存储层次与 Cache:局部性原理让"小而快"的 L1/L2/L3 能吸收"大而慢"的主存 / 外存延迟,层层降速换取容量与成本优势。
  • 总线:地址(单向)/ 数据(双向)/ 控制(双向)三线共享,是冯诺依曼瓶颈的物理载体;EC 正是靠最老派的端口 I/O(0x62/0x66)挂在总线上。
  • I/O 三种方式:轮询占满 CPU、中断按需打断、DMA 绕开 CPU 直接搬数据,是"谁来搬数据"这个问题的三种答案。
  • Turbo Boost 与散热降频呼应第 08/09 章:流水线执行 → 发热 → 触及功耗 / 电流 / 温度上限 → 动态降频,EC 独立决定风扇转速——这条因果链把本章所有机制串成了一件真事。
